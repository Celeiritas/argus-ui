## 4.42.0 – 2026-11-13
- **A static plugin can have its own address.** A game in the sandboxed frame has an opaque origin: no browser cache it can keep, no storage, no frames of its own pages, no downloads. A plugin named in the host's `~/.config/argus-ui/own-origin.json` (never in git; `ARGUS_OWN_ORIGIN` points elsewhere) now also gets a second listener on 127.0.0.1 in the same process, published by `tailscale serve` on its own HTTPS port. There it is a normal page on its own origin, and all of those work. No file: nothing changes. The file is read when Argus starts; a broken file or entry is logged and left out, and never stops Elaia.
- **Open Spartamelee.** Its section in Elaia is then a large **Open Spartamelee** button (56 px, keyboard reachable) that opens the game in its own tab, plus its extra pages from the file (**Frame data** → `frames/`), and no frame. The address is the host name Elaia was opened at with the plugin's HTTPS port when the page came through `tailscale serve`, or `http://127.0.0.1` with the local port on the server itself. Elaia offers it only where the browser can reach it: opened any other way (another device over plain http with `ARGUS_BIND=0.0.0.0`), the sandboxed frame stays. A link with no page behind it, or one that leads out of the folder, is left out. Without an own address the sandboxed frame stays exactly as it was.
- **The second listener only serves files.** It answers GET and HEAD only (anything else is 405); `/` is the plugin's entry page. It refuses every path outside the plugin's folder (`..`, encoded dots, backslashes, drive paths, symlinks out, a folder's `index.html` that is a link out included; Elaia's own `plugins/<id>/` gets the same check). It has the same host check, identity and roles as opening the plugin inside Elaia, and the same caching (ETag, Last-Modified, 304, a year for hashed names). There is no API, no POST and no CORS header. Its CSP fits a game on its own origin (framed by nobody else), with no sandbox.
- **Elaia stays shut to it.** A different port is a different origin. The game's POSTs fail the Sec-Fetch-Site and Origin checks, and it cannot read any Argus answer, because none carries `Access-Control-Allow-Origin`. Plugin frames still never get `allow-same-origin`.
- **Cookies of any size are skipped.** Cookies belong to the host name, not the port, so the game can set cookies the browser then sends to Elaia; past 64 KB the standard library answered every request with 431, which would have locked Elaia. Argus reads no cookies: both listeners now skip every `Cookie` line while reading a request (up to 4 MB), so a page that piles them up changes nothing.
- **A mistake never stops Argus, and a taken port is loud.** A host file nested too deep to read is ignored like any broken file, and any other failure while starting the own listeners is logged, never fatal. A plugin whose local port is taken at start keeps its frame and raises an `argus-own-origin` alert in Watch (docs/alerts.md), which says to turn off that port's `tailscale serve` mapping, because Serve keeps forwarding to whatever holds the port. With several taken ports the instruction comes first and names each public port (or the count and the first one's command), within the 300 characters Watch shows. Only a start that finds no host file, or reads it cleanly with no plugin left out and starts every own listener, clears the alert; an unreadable file or a skipped entry keeps it.
- **Small checks.** A plugin id (a folder's or the host file's) or an own-address link ending in a newline is refused (`fullmatch`, since `$` alone allowed one). A path the server cannot compare with the plugin's folder (another drive on Windows) is outside it: 404, never 500, also for the folder-slash redirect and `static/`.
- Docs: `docs/leafy-plugin.md` "Its own address". Tests:
  - `tests/own_origin_test.py` checks the file's rules, the listener's paths (an `index.html` that links out too), methods, roles and caching, every POST route from the game's origin, that no API answer carries access-control headers, a 900 KB Cookie header on both listeners, the busy-port alert (when it stays, when it goes, how many ports fit) and where the own address is offered;
  - `tests/own-origin.test.js` checks the button, the keyboard path, the new tab, storage kept across a reload, Elaia out of the game's reach, `frames/`, and 375 px.

## 4.39.0 – 2026-11-11
- **Phone alerts: the phone buzzes, also when Elaia is closed.** The page installed as an app on the phone (no separate app) gets real notifications by the web's own standards: each message is encrypted for that one phone (RFC 8291, `aes128gcm`), so the browser's push service (Google's for Chrome; corrected in 4.43.0, it said the phone maker's) carries it but cannot read it, and every request is signed with the server's own key (RFC 8292, VAPID). It buzzes for exactly three kinds, each a switch per phone in the owner's words: **Something stopped working** (`broke`), **Something needs my yes** (`needs-yes`), **Daily summary**. A repair Argus did by itself (`fixed`) or something that came back on its own (`recovered`) never buzzes: it stays on the page and goes into the summary. The same thing does not buzz again within 30 minutes; at most 6 buzzes per person in any hour, and what comes after is folded into one later message ("3 more things happened. Open Elaia."). Only owners' devices get alerts, at most 8 per person. New module `server/push.py`; it needs the `cryptography` package, imported only when needed: without it the page says "not available on this server" with the reason and everything else works as before.
- **The server only ever calls a known push service:** `https`, port 443, and a host that is `fcm.googleapis.com` or ends in `.push.services.mozilla.com`, `.notify.windows.com` or `.push.apple.com`, checked when a phone is added and again before every message; no user-info, no IP address, no redirect followed. Sending runs on its own thread with a small queue (10 seconds per try), so neither the checks nor the page wait on the network; a phone that is gone (404, 410) is removed, a busy or silent service (429, 5xx, no answer) gets one more try a minute later, then the reason in plain words next to the device. The server's key pair (`~/.config/argus-ui/push-key.pem`) and the devices (`~/.local/state/argus-ui/push-devices.json`) are mode 600, written through a temp file and renamed; a device's address is never logged or sent back to the page.
- **The daily summary** (`server/summary.py`, its own small thread): once a day at `ARGUS_SUMMARY_AT` (default 08:00) one `summary` event with a title a tired person understands ("Yesterday: everything worked", "Yesterday: 1 thing stopped working, Argus fixed it", "1 thing is waiting for your yes") and at most three short sentences from the last 24 hours' events and the checks as they are now. ## 4.1.0 – 2026-10-18
UX audit (VectorLab UX skills) and security review.
- **Type:** 16/14/12px scale (no text under 12px), task details at 14px, weights 400/600 only, body line-height 1.5
- **Targets:** every control has a 44px hit area; nav links and the log toggle are 44px tall
- **Keyboard:** Medusa and Zeus's bolt are real buttons. Press one, then Enter on a task (Esc cancels). Tooltips show on hover *and* focus. Argus's eyes follow keyboard focus too.
- **Confirm before interrupting:** freezing or restarting a task that is running right now asks first (named task, Cancel focused, Esc cancels). Freezing anything else offers **Undo**.
- **Copy:** verb-first buttons ("Show log", "Mute sounds"), plain-language results, errors say what happened and what to do next
- **Motion:** UI transitions use 150/200/300ms tokens and only transform/opacity; tools fly with transforms; reduced-motion skips particles and strikes (fade only); Argus stops wandering/blinking under reduced motion
- **Layout:** header is full width (only main content is capped); counts are plain text, not pills; sound toggle moved into the nav
- **Security:** CSRF and DNS-rebinding protection, `ARGUS_BIND`, `ARGUS_ALLOWED_HOSTS`, safe static paths, body size cap, `</script>` escaping, a lock around freeze/thaw, atomic frozen-list writes, and systemctl failures are reported instead of ignored
