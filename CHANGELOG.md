# Changelog

## 4.37.0 – 2026-11-11
- **The page knows who is asking.** Behind `tailscale serve` every request carries the sender's Tailscale login (`Tailscale-User-Login`). The server now believes that line **only when the connection really comes from Serve**: it looks the connection up in the kernel's tables (`/proc/net/tcp`, `/proc/net/tcp6`, no sudo needed) and checks that the other end belongs to the Serve user (user id `0`, where `tailscaled` runs; `ARGUS_SERVE_UID` changes it). A program on the server that connects to the page's port and sends the line itself, a machine without `/proc`, or a closed connection: no identity. (A program that goes in through Serve's own front door is caught by the rule below.) New module `server/identity.py` (standard library only), packaged and installed next to `sky.py`.
- **People and roles.** `~/.config/argus-ui/people.json` (`ARGUS_PEOPLE`) lists people, their Tailscale logins and a role: `owner` (everything) or `learner` (Today and the study pages). A listed, trusted login is that person; anyone else is *no role*. The file is read again when it changes (no restart). **Without the file nothing changes**: everyone is the owner, "You", as before. A file the server cannot use (not JSON, no owner, one login under two people, a role it does not know ...) keeps the last good copy and tells the owner; if no good copy is known, the page is closed to everyone (only `api/health` and `api/whoami` answer) and the private page tells the owner how to get back in. `docs/people.md` explains it for the owner, with what to do when locked out.
- **A role gate in front of every route.** Everything is the owner's unless opened: anyone may ask `api/health` and the new **`api/whoami`** (`login`, `trusted`, `through_serve`, `person`, `name`, `role`, `problem`: how to see who the server thinks you are, before writing the people file); a learner gets the page and its files, `api/sky`, and a cut-down `api/state` (her role and name and the places she may open; no tasks, alerts, links, watch rows); program logs, Freeze, Thaw, Restart and Run are the owner's. `api/state` carries `role`, `person`, `name`, and for the owner `people_problem`.
- **Plugins:** `plugin.json` may open paths to learners (`"roles": {"get": {"today": "learner"}, "post": {...}}`); a plugin's files are open to a learner only if it opens a path; static plugins stay the owner's. A `get`/`post` with a fourth parameter gets `who = {person, name, role}` on every call, never `None`; roles are checked before the plugin is called. `ctx.headers` drops `Tailscale-*` and `X-Forwarded-For` unless the request came through Serve, so no plugin is handed a faked name.
- **Refusals say what happened:** an `api/...` call answers `403 {"error": "<one sentence>"}` (also as `msg`); a page address opened by someone without a role gets one small private page (no script, light and dark) naming the login the server saw, or that the request did not come through Tailscale.
- **After the security review (R5):** a request that comes through Serve **from the server itself** (a program using the server's own tailnet address, which Serve stamps with the server's own login) carries no identity: if any address in Serve's `X-Forwarded-For` is this machine's own (loopback included), the login does not count, and `api/whoami` says so (`from_this_server`, `note`); another device's address, a missing header or a value that is not an address changes nothing. Every good read of the people file is saved (`~/.local/state/argus-ui/people.last-good.json`, mode 600, `ARGUS_PEOPLE_LAST_GOOD`), so a restart, a deploy or a file that went away for a moment never turns a broken file into "everyone is the owner"; a link to a missing file, an `ARGUS_PEOPLE` path with nothing at it, and any unexpected error while reading are an unusable file, never "no file"; an unusable file with no good copy known closes the page to everyone (the hub's decision) with a plain way back on the private page; a file whose owners have no login is refused; the reason names entries by number, never a login, a name or a path. `ARGUS_SERVE_UID` set to the page's own user is refused with a loud log line (allowed only with `ARGUS_DEV`, for tests). The connection lookup also matches the server's own end by its socket's inode. A plugin's `who` may be keyword-only. The private page tells an owner locked out on his own device what to do. The owner sees a people-file problem as one plain line on Today and Watch. A learner who opens an owner's address (Watch, the Throne) is sent to Today. `scripts/install.sh` checks `api/health` after an install (the page itself answers this machine with 403 once a people file exists).
- **Security quick wins:** the server listens on `127.0.0.1` unless `ARGUS_BIND` says otherwise (was `0.0.0.0`; the installer already set it); every answer that is not a plugin file carries `X-Frame-Options: SAMEORIGIN`, `Content-Security-Policy: frame-ancestors 'self'`, `X-Content-Type-Options: nosniff` and `Referrer-Policy: same-origin`; `Access-Control-Allow-Origin: *` only on a static plugin's files, never on a server plugin's.
- Tests: `tests/identity_test.py` (the tables: IPv4, IPv6, IPv4 in the IPv6 table, no row, garbage, owner root or someone else, closed sockets never root, and on Linux a real connection; the people file and its failure cases), `tests/gate_test.py` (every route against owner, learner and no role on a real server, with the real `/proc` lookup on Linux; the learner's state; `who`; Home's lines; a faked login on a direct connection; the people file broken at start, after a good read, changed on disk, two owners; the headers). `tests/run.sh` runs them under "== people and roles" and runs its server as the Serve user (`ARGUS_SERVE_UID=$(id -u)`). `tests/people.test.js`: a learner, the owner and a stranger in the real page with a real people file (her bar, Today when she opens Watch, refused logs and Restart; the owner unchanged; the private page; a request from the server itself; the file moved aside restores everything at once). `tests/mentor_gate_test.py`: the real Mentor end to end, skipped (and said) until a Mentor with `"roles"` is in the build. A test checks that every route in `H.get()` / `H.do_POST()` is in the route list.

## 4.35.0 – 2026-11-11
- **Argus notices a program that runs but cannot do its job.** A new background loop (`server/watch.py`, every 60 seconds, in its own thread) reads checks from `~/.config/argus-ui/checks.json` (no file: no checks) and proves each program works, not only that it is up: its unit is active, its drive is in the mount table (`/proc/self/mountinfo`, no sudo) and writable, its container holds **no dead copy of the drive** (a mount line with `shutdown`, a drive the host no longer has, or, with the new `container.mount`, a bound folder that is not on the host's drive: a container started before the drive was there) and can read a named file or folder, an http address answers. The mount table is read first and **no file is read on a drive that is missing, dropped or read-only**; a check that names a file without its drive is refused. A read inside a container and an http call get 6 seconds, `systemctl` calls the server's own 20 seconds; `state()` only reads the last results, so a hung check cannot block the page; stale results turn unknown. A test read that hangs is not repeated for 15 minutes (or until the drive's mount line changes) and shows as a `warn` note: *Media player does not answer when it reads its drive*. Built for the case where a USB drive came back under a new name and Jellyfin kept a dead copy for 26 hours while its unit read active and its health check said healthy.
- **Each program gets `works: true | false | null` and a plain reason** in `state()` (`watch`, and `works` / `works_reason` on the task cards the checks name). A failed check with a `job` also shows as a card note through the alert path, so Argus glares and the badge counts it: *Running, but not working: cannot read its drive*.
- **Events, one per change of state** (`server/notify.py`): `{id, at, kind, subject, title, body, url, level}` with `kind` `broke`, `needs-yes`, `fixed`, `recovered` or `summary`, written to a capped file (`~/.local/state/argus-ui/events.jsonl`, newest 500). A repeat of the same failure raises nothing, and neither does restarting the server. Programs that depend on a drive that has its own failing check stay quiet (one event for the drive, not four), and stay quiet when it comes back (no `recovered` for them either). More sinks are added with `notify.register()`.
- **A failure counts once it is seen in 2 rounds in a row** (one slow answer is not a breakage; an unknown round in between starts the count again); getting better counts at once. A unit that is `activating`, `reloading` or `deactivating` is "cannot tell yet", unless it stays so for more than 3 rounds.
- **Self-repair ships off, starts as a trial, and is narrow.** `~/.config/argus-ui/auto-fix.json` is `{"ids": [...], "trial": true|false}`; no file, a file that is not JSON or a file of another shape means off (one log line). It acts only when the program **runs but cannot read its drive** (`dead-copy`, `cannot-read`), never on a slow web answer, a unit that is down or starting, or a hung read. **Trial is the default:** unless the file says `"trial": false`, nothing is restarted and one `needs-yes` says what Argus would have done. At most **one try per check in 24 hours**, the time saved to disk before the restart and kept across recovery and server restarts; each unit at most once per round; a restart command that hangs or fails counts as not working and the round still finishes; a restarted program gets up to 90 seconds (the power buttons' lock is not held while it waits). **Self-repair waits for its own 2 rounds:** the code it acts on must itself be seen 2 rounds in a row, also when the program was already failing for another reason. **Only a failed read counts as "cannot read its drive":** exit code 1 or 2 from `head` / `ls`, or nothing read; podman's own errors (125, 126, 127), a signal or any other exit code make the check unknown and never restart anything. Every other failure with a named fix raises `needs-yes`.
- **The card says what Argus did about it** when the check has a `fix`: *Argus would have restarted ... by itself and did not, because for now it only notes what it would do* on the trial day, *Argus did not restart it and waits for your yes* when it may not or has used its try, and the plain truth after a restart that did not help or did not work. A container that never had its drive (found through `container.mount`) gets its own explanation instead of "unplugged and came back".
- `tests/run.sh` honours `PYTHON=${PYTHON:-python3}`, gives the server `USERPROFILE` next to `HOME` and explicit `ARGUS_EVENTS` and `ARGUS_WATCH_STATE` paths, so a run never writes into a real profile (on Windows `~` follows `USERPROFILE`). Unit and container names may not start with `-`. `scripts/build.sh` and `scripts/install.sh` carry `watch.py` and `notify.py`. Docs: `docs/checks.md`.
- Tests: `tests/watch_works_test.py` (75 tests: podman's exit codes 125/126/127/137 never read as a broken drive and never restart, one round of *cannot read* after another failure does not restart and two in a row do (once a day), fail-unknown-fail is not two, the card's words in each case, the two dead-copy stories; no restart for a slow web answer or a unit that is down, a flapping program restarted once in 24 hours also across a restart of argus-ui, the mark on disk before the restart, a unit once per round, trial by default with its words, a broken or odd `auto-fix.json` turns self-repair off with one log line, starting units, two rounds before a failure counts, a hung read neither repeated nor silent, `container.mount` for a container that bound the empty folder and for a reused device number, no `recovered` for quiet programs, a restart that raises, the 90-second wait outside the power lock, names starting with `-` refused; and canned mount tables for good, missing, read-only, dropped; dead copy by the word `shutdown` and by a gone device; the incident replayed with the unit active and health 200; no file read on a bad drive or in a dead container; one event per change; recovered once; nothing restarts without `auto-fix.json`; approved restart then `fixed`; a restart that does not help is tried once; frozen is paused; unknown never raises; config refusals; a hung call ends at its timeout; stale results; a real server in its own process), `tests/works.test.js` (the card, the glare, the event file, the card going away, 375 px), fixtures `tests/fixtures/watch/` and `fake_podman.py`. `bash tests/run.sh works`.

## 4.32.0 – 2026-11-09
- **Four new kinds of card for reading and writing code** (Mentor courses, phase 4). **Predict**: read a short piece of code and type what it prints. **Trace**: type what a name holds after each step ("Step 2: after line 3"). **Put the lines in order** (a Parsons puzzle): the lines of a function come mixed; move them with **Up** and **Down**. **Write the code**: write a small function, starting from its first line. Reading comes before writing in a lesson.
- **Grading:** predict and write cards by key ideas against the model answer (in code, words like `for` and `in` count); trace cards step by step, a value counting only in its own step; Parsons by exact order, with a point for each line in its right place (4 of 5 lines = 80%). Written code is only read, never run; Python's own syntax error is shown next to the key ideas. A trace or Parsons answer that is not a plain list of values (a list of lists, or JSON nested deeper than Python reads) is graded as one typed answer instead of failing the request. If the local AI is on, it scores written code beside the grade, labelled, and never sets the rating or writes cards.
- **Parsons by keyboard:** every line has 44 px Up and Down buttons; focus stays with the line you move, Alt+↑/↓ moves it too, and a screen-reader line says where it went ("Line moved to place 2 of 5", or "already first"). Nothing needs a drag.
- **Lessons unlock in order.** A course lesson can require other lessons; it opens when each of them is **mastered**: 80% of its cards answered right (Good or Easy, no hint above the second rung). Until then it is shown as **Locked** with what opens it, choosing it says the same, and its cards don't count as new. A module that requires another module waits the same way. Lessons outside a course never lock. *80% is the spec's default.*
- **Module checks:** once every lesson of a module is mastered, its check questions come, once each, marked as the module check and never scheduled for practice. The check passes at 80% right; a missed question comes back the next day. With bury siblings on (the default), a check question from a note practised today waits until tomorrow too, and the map says so (*Module check ready: 4 questions tomorrow*), so the map, the counts line and the queue always agree.
- **The course map** (Lessons) shows each module of a course with its lessons under it: how many lessons are mastered or that it is locked, a bar for the share answered right, and its check (waiting, ready, passed, not passed yet). Each lesson row says "75% right", "100% right · mastered" or "Locked". The counts line and Home's line count the module check questions that are ready.
- **The checker** (`scripts/check-deck.py`) knows the new cards: C10 predict, C11 trace, C12 parsons, C13 write (each card's required fields, and its Python parses: a code card without `lang` is Python, as Mentor reads it; another language is named as not parsed), and C5 now checks a lesson's `requires` (a lesson of the course, no circles). Docs: `docs/mentor.md` (Code cards, unlocking and module checks), `docs/mentor-rubric.md`.
- Database: one new column, `modules.requires`, added on start; starting twice changes nothing more.
- Tests: `tests/mentor_model_test.py` (importing the four roles; the page never gets the answer, the trace values or the right order; grading each role, partial credit included; the hint ladder; a lesson locked until the one it requires reaches 80%, Hard or a third hint not counting, undo locking it again; the module check after both lessons, a missed item back the next day, undo of a check answer; a module locked by its required module; Loose lessons never locked; upgrading twice; the checker on each bad fixture and odd values; a card without `lang` still parsed; deeply nested and nested-list answers graded as text; with bury siblings on, the check waits a day and the map, counts and queue agree), fixtures `tests/deck-fixtures/good-roles.json` and `bad-predict.json`, `bad-trace.json`, `bad-parsons.json`, `bad-write.json` (run by `tests/run.sh`), `tests/mentor.test.js` (each role's card by keyboard, the Parsons keyboard path and 44 px buttons, the locked lesson and its words, the module check, the course map, 375 px).
